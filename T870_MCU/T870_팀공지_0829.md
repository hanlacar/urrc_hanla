# 1. 🔴 odom 거리가 실제의 37.5% 만 나오고 있었습니다

## 무슨 일이었나

`counts_per_meter` 설정값이 틀렸습니다.

```
설정값   533.1
실측     199.8      (955 카운트 / 4.78 m)
```

**실제로 10m 를 가면 odom 은 3.75m 라고 보고했습니다.**

## 어떻게 측정했나

ROS 를 완전히 빼고 **아두이노 단독 스케치**로 쟀습니다.
중간에 끼어드는 노드가 없어 결과가 깨끗합니다.

```
2단(PWM 100), 10초 전진, 하중 실린 상태
총 카운트 955,  실측 이동거리 4.78 m (앞바퀴 동일 지점 기준)
```

내부 검증 — 서로 다른 두 경로가 같은 값을 냅니다.

| 방법 | 결과 |
|---|---|
| 총합 계산 955 / 4.78 | cpm **199.8** |
| 정속구간만 99.6 카운트/s ÷ 0.5 m/s | cpm **199** |
| 평균 속도 4.78/10.5 = 0.455 m/s | 2단 문서값 0.526 과 정합 ✅ |

## 왜 지금까지 몰랐나 — 엔코더 노이즈

이전 측정들이 서로 안 맞았던 이유를 찾았습니다.

ROS 스택을 돌리며 **정지/출발이 잦았던 세션**에서 카운트율이 **550개/초**까지
올라갔습니다. 그 속도면 2.75 m/s 인데 **이 차 최고속은 0.82 m/s** 입니다.
대부분이 브러시 노이즈로 생긴 **가짜 펄스**였습니다.

원인은 디바운스 설정이었습니다.

```
진짜 펄스 간격 (3단 기준)   6.1 ms
디바운스 설정               0.2 ms   ← 실제 간격의 1/31. 사실상 무방비
```

→ **2 ms 로 올렸습니다.** 3단 기준으로도 여유가 3배라 진짜 펄스는 하나도
잃지 않으면서 노이즈만 10배 더 걸러냅니다. (펌웨어 v34)

🔴 **중요**: 모터 스위칭이 잦을수록 노이즈가 심해집니다.
급정거·출발정지가 반복되는 **대회 주행이 정확히 그 조건**입니다.

## 각 팀에 미치는 영향

# 2. 🔴 카메라팀 — 두 줄만 고쳐 주세요

## (1) `course_mission_node.py` 269행 — E-Stop 반복의 원인

```python
# 이전
self.camera_stop_pub.publish(Bool(data=bool(output.stage == 0)))

# 이후 — 진짜 비상일 때만
self.camera_stop_pub.publish(Bool(data=bool(output.emergency)))
```

**왜**: MCU 계약에서 `/<팀>_stop` 은 **급정거(비상정지)** 입니다.
"내가 속도 0 을 명령 중" 이 아니라 **"당장 세워라"** 라는 뜻입니다.

```
판단 로직 켬 → 인지 준비 안 됨 → stage 0
   → /camera_stop=true → EMERGENCY_STOP(camera)
인지 잡힘 → stage 1 → false → 해제
다시 stage 0 → 또 EMERGENCY_STOP
```

"E-Stop 이 떴다 해제됐다 반복" 이 이것입니다.
인지가 계속 실패하면 stage 가 0 에 머물러 **그대로 유지**됩니다.

🔴 **더 중요한 이유**: 펌웨어 v33 부터 급정거가 **모터 역토크(다이내믹
브레이킹)** 로 바뀌었습니다. 예전 0.5초 감속 램프가 아닙니다.
stage 0 이 될 때마다 모터에 역토크가 걸려 **모터·기어·드라이버에 부담**입니다.

※ `stage = 0` 은 `/camera_drive` 로 이미 전달되어 정상 정지합니다.
   `/camera_stop` 은 충돌 임박 같은 상황에만 쓰세요.

## (2) `autonomy_output_node.py` 70~71행 — 없는 토픽을 듣고 있습니다

```python
# 이전 (하드코딩이라 런치 인자로 못 고칩니다)
self.create_subscription(Bool,    "/vehicle/speed_valid", ...)
self.create_subscription(Float32, "/vehicle/speed_kph",   ...)

# 이후
self.create_subscription(Bool,    "/mcu/speed_valid", ...)
self.create_subscription(Float32, "/mcu/speed_kph",   ...)
```

MCU 는 `/mcu/speed_*` 로 발행합니다. `/vehicle/speed_*` 는 **아무도 발행하지
않습니다.** → `observation.speed_valid` 가 **항상 false** 입니다.

`course_mission_node` 쪽은 파라미터라 `mcu_ws_autonomy.launch.py` 로 띄우면
괜찮지만, 이 두 줄은 하드코딩이라 **코드를 고쳐야만** 합니다.

# 4. 🟡 라이다팀

## 급정거가 실제로 강해졌습니다

`/lidar_stop` 을 걸면 예전에는 **0.5초 감속 램프**가 나갔습니다.
설정이 옛 버전 그대로여서 만들어 둔 제동 명령을 쓰지 않고 있었습니다.

지금은 **모터 역토크**가 나갑니다. 같은 신호에 훨씬 급하게 섭니다.
시뮬 튜닝이 예전 반응 기준이면 다시 보셔야 합니다.

## 주차 진입 — 0.5m 정지선이면 못 들어갑니다

시뮬 기록상 주차 완료 시 뒷범퍼 간격이 **0.276 ~ 0.377m** 입니다.
0.5m 에서 멈추면 진입 자체가 불가능합니다.

`/mcu/current_mode` 를 구독해 주차 모드에서 임계값을 낮추는 방식을 제안합니다
(예: 0.15m). 라이다 데이터를 보는 판단이라 라이다팀에서 하는 게 맞습니다.
**절대 하드정지 0.15m 는 모드 무관 유지** 해 주세요.

## 감속 방식을 정해 주세요

"0.5~1.5m 에서 속도 1단계 낮춤" 을 `/lidar_drive` 로 직접 쏘면, 현재 구동
우선순위가 **라이다 > 카메라 > GPS** 라서 **모든 구간에서 라이다가 구동을
독점**합니다. 카메라 속도 명령이 전부 무시됩니다.

| 안 | 방식 | 비용 |
|---|---|---|
| **A (권장)** | 라이다는 `/lidar_slow`(Bool)만 발행, MCU 가 한 단계 낮춤 | MCU 약 30줄 |
| B | 우선순위를 카메라 > 라이다 > GPS 로 변경 | yaml 한 줄 |
| C | 현행 유지 (독점 수용) | 없음 |

# 5. 🟡 시리얼 포트 — 아두이노에 붙는 노드는 하나만

`race_vehicle_interface` 안에 아두이노 시리얼 브릿지가 **두 개 더** 있습니다.

```
arduino_serial_bridge_node   → /dev/ttyACM0  (하드코딩)
encoder_serial_bridge_node   → /dev/ttyACM1  (하드코딩)
```

MCU 브릿지와 동시에 실행하면 **포트 충돌** (`[Errno 16] Device or resource busy`).

✅ `mcu_ws_autonomy.launch.py` 는 이걸 안 띄웁니다. **MCU 연동 시 이 런치만
쓰세요.** `vehicle_stack.launch.py`, `full_vehicle_autonomy.launch.py` 는 충돌합니다.

⚠️ 포트 번호는 꽂는 순서마다 바뀝니다. `/dev/ttyACM0` 이 GPS 일 수 있습니다.
MCU 는 udev 로 `/dev/t870_mcu` 를 고정해 씁니다.
