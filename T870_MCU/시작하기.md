# T870 MCU — 시작하기

처음 받았으면 **위에서부터 하나씩** 실행하면 됩니다.
Ubuntu 22.04 / 24.04 + ROS 2 기준입니다.

> **0829 갱신**
> - `counts_per_meter` 533.1 → **199.8** (실측). odom 거리가 2.67배 정확해졌습니다
> - 펌웨어 최신 = **v34** (엔코더 노이즈 차단 강화)
> - 팀별 수정 요청은 같은 폴더의 `T870_팀공지_0829.md` 를 봐 주세요
>
> ⚠️ **odom 값이 크게 바뀌었습니다. 거리 기반 튜닝값을 다시 확인해 주세요.**

---

## 1. 압축 풀기

원하는 위치 아무 데나 됩니다. (`~/mcu_ws` 를 예로 듭니다)

```bash
unzip T870_MCU_배포_0829.zip -d ~ && mv ~/T870_MCU ~/mcu_ws && cd ~/mcu_ws
```

## 2. 설치 (한 번만)

포트 권한과 udev 규칙을 잡습니다. sudo 비밀번호를 물어봅니다.

```bash
chmod +x setup.sh && ./setup.sh
```

## 3. 빌드

```bash
cd ~/mcu_ws && colcon build --symlink-install
```

## 4. 환경 적용

**새 터미널을 열 때마다** 해야 합니다.

```bash
source ~/mcu_ws/install/setup.bash
```

매번 치기 귀찮으면 한 번만:

```bash
echo "source ~/mcu_ws/install/setup.bash" >> ~/.bashrc
```

## 5. ROS_DOMAIN_ID 맞추기 🔴

**전 팀이 같은 값이어야 합니다. 다르면 토픽이 안 보이고 에러도 안 납니다.**

```bash
export ROS_DOMAIN_ID=10
```

이것도 `~/.bashrc` 에 넣어두면 편합니다. **모든 터미널에 적용되어야 합니다.**

## 6. 아두이노 연결 확인

USB 를 꽂고:

```bash
python3 ~/mcu_ws/tools/check_ports.py
```

`/dev/t870_mcu` 가 보이면 성공입니다.
안 보이면 **USB 를 뽑았다 다시 꽂고** 다시 실행하세요 (udev 규칙 적용에 필요).

## 7. 실행

```bash
ros2 launch t870_mcu t870_mcu.launch.py
```

**포트를 적을 필요가 없습니다.** 알아서 찾습니다.

시작하면 이런 줄이 보여야 정상입니다.

```
udev 심볼릭 링크 사용: /dev/t870_mcu -> /dev/ttyACM0
mcu_bridge v3: ... cpm=199.80, 급정거=B(1회) → 1.00(반복)
[MCU] MCU_BOOT,v34
```

`[MCU] MCU_BOOT,v34` 가 안 뜨면 아두이노 펌웨어가 최신이 아닙니다. MCU 담당에게 알려주세요.

## 8. 키보드로 조종해 보기 (선택)

위를 켜 둔 채 **다른 터미널**에서:

```bash
python3 ~/mcu_ws/tools/drive_wasd.py
```

```
0  ★ 조종권 토글 (대기 <-> 키보드 전용)
W 전진   S 후진   A 좌   D 우   C 중앙
Space 정지   F 급정거   E E-Stop   R 래치해제
Q 종료
```

**처음엔 "대기" 상태입니다.** 카메라/라이다/GPS 가 차를 몰고 이 도구는 보고만
있습니다. `0` 을 눌러야 키보드가 차를 잡습니다.

조종 중에 `0` 을 누르면 먼저 정지만 하고, 한 번 더 눌러야 팀에게 넘어갑니다.

`F`(급정거)와 `E`(E-Stop)는 **대기 중에도 항상 동작합니다.** 안전요원 역할입니다.

팀 노드 없이 혼자 시험할 때는:

```bash
python3 ~/mcu_ws/tools/drive_wasd.py --takeover
```

⚠️ 첫 주행은 반드시 **1단**으로, 앞 공간을 확보하고 하세요.
⚠️ `F`(급정거)는 모터 역토크를 겁니다. 지면에서 처음 쓸 때는 앞을 비워 두세요.

# 내 노드에서 쓰는 법

## 발행 (팀 이름은 camera / lidar / gps 중 하나)

```
/<팀>_drive   std_msgs/Float32   0 정지 / 1 2 3 전진 / -1 후진   ← 이 5개만
/<팀>_wheel   std_msgs/Int32     -27 ~ +27 도,  + 가 우측
/<팀>_stop    std_msgs/Bool      true = 급정거 (비상). 아래 주의 참고
```

**최소 4Hz 로 계속 발행하세요.** 값이 안 바뀌어도, 정지 중에도 계속 보내야 합니다.
0.5초 끊기면 죽은 소스로 판정하고 다음 팀으로 넘어갑니다.

🔴 **`/<팀>_stop` 은 "급정거" 입니다.** "내가 속도 0 을 명령 중" 이 아닙니다.
`true` 를 보내면 모터에 역토크가 걸립니다. 그냥 서고 싶으면 `drive = 0` 만
보내세요. `_stop` 은 충돌 임박 같은 상황에만 쓰세요.

## 구독 (자주 쓰는 것)

```
/mcu/encoder      std_msgs/Int32     ★반드시 Int32. Float32 로 받으면 조용히 실패
/mcu/distance_m   std_msgs/Float32   누적 거리 [m]
/mcu/speed_mps    std_msgs/Float32
/mcu/speed_valid  std_msgs/Bool
/odom             nav_msgs/Odometry  공분산 포함
/mcu/fw_state     std_msgs/String    READY / ACTIVE / FAULT / ESTOP
/mcu/fw_message   std_msgs/String    펌웨어 원문 (MCU_BOOT, BRAKE_DONE ...)
/mcu/current_mode std_msgs/String
/mcu/active_drive_source   std_msgs/String   지금 누구 명령을 따르는 중인지
/mcu/active_wheel_source   std_msgs/String
```

⚠️ 토픽 이름은 `/mcu/...` 입니다. `/vehicle/...` 은 아무도 발행하지 않습니다.

## 서비스

```bash
# E-Stop 래치 해제 (/estop_lock 은 래치라 false 를 보내도 안 풀립니다)
ros2 service call /mcu/reset_estop std_srvs/srv/Trigger '{}'

# 오도메트리 원점 재설정
ros2 service call /mcu/reset_odom std_srvs/srv/Trigger '{}'
```

일시 정지는 `/estop_lock` 말고 `/<팀>_stop` 을 쓰세요 (0.5초 후 자동 해제).

## 모드

`/vehicle_mode` (String) 로 구간을 알립니다. **아래 이름만 인식합니다.**
오타가 나면 ERROR 로그를 찍고 직전 모드를 유지합니다.

```
IDLE  START  SLOPE  CRANK  INTERSECTION_1  S_COURSE  INTERSECTION_2
T_PARK  INTERSECTION_3  ACCELERATION  PARALLEL_PARK  FINISH  SUDDEN_STOP
```

주차 모드(`T_PARK`, `PARALLEL_PARK`)에서만 조향 권한이 라이다로 넘어갑니다.

# 도구

전부 `--help` 로 옵션을 볼 수 있습니다. **토픽 이름은 코드에 박혀 있지 않습니다.**

| 도구 | 용도 | 주요 옵션 |
|---|---|---|
| `check_ports.py` | 포트 확인. `/dev/t870_*` 고정 이름부터 표시 | `--probe` |
| `drive_wasd.py` | 키보드 조종 | `--takeover` `--source` `--mcu-ns` |
| `odom_calib.py` | odom 거리 검증 | `--mcu-ns` |
| `team_monitor.py` | 각 팀 토픽 수신 상태 | `--mcu-ns` `--<팀>-drive` |
| `mode_sim.py` | 차 없이 중재 로직 확인 | `--mcu-ns` `--mode-topic` |
| `measure.py` | counts_per_meter 실측 | `--port` `--distance` |

# 안 될 때

| 증상 | 해결 |
|---|---|
| `아두이노를 못 찾았다` | USB 확인 → `python3 tools/check_ports.py` |
| `Device or resource busy` | 다른 프로그램이 포트 사용 중. **아두이노 IDE 시리얼 모니터를 닫으세요** |
| | `sudo fuser -k /dev/t870_mcu` |
| `Permission denied` | `./setup.sh` 다시 실행 |
| `Package 't870_mcu' not found` | `source ~/mcu_ws/install/setup.bash` 안 함 |
| 토픽이 안 보임 | `ROS_DOMAIN_ID` 확인. **전 팀 같은 값이어야 함** |
| 텔레메트리 `두절` | 펌웨어가 안 올라갔거나 다른 스케치. `[MCU] MCU_BOOT,v34` 확인 |
| 차가 안 움직임 | 조종 화면이 **초록색 "조종 중"** 인지. 노란색이면 `0` |
| 빌드가 이상하게 실패 | `rm -rf build install log` 후 다시 빌드 |

# 펌웨어

## 🔴 팀원은 펌웨어를 올리지 마세요

`firmware/` 는 **참고용** 입니다. 차량 탑재는 MCU 담당이 합니다.

- 버전이 갈라지면 차에 무엇이 올라가 있는지 아무도 모르게 됩니다
- 현재 버전은 브릿지 로그의 `[MCU] MCU_BOOT,vXX` 로 확인할 수 있습니다

| 버전 | 내용 |
|---|---|
| v31 | 조향 ADC 폐루프 시도 |
| v32 | `ENCODER_CPR` 정정 시도 |
| v33 | 제동을 고정 시간 → 엔코더 피드백으로 |
| **v34** | `ENCODER_CPR` 163, 디바운스 200us → 2ms (노이즈 차단). **현재 차량 탑재** |

`firmware/측정용/` 의 스케치는 counts_per_meter 실측 전용입니다.
ROS 없이 아두이노 단독으로 동작하며, **워치독도 안전 상태머신도 없습니다.**
측정 후 반드시 v34 로 되돌려야 합니다.
